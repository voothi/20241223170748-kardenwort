# RFC: v1.48.2 - Flexible Anki Field Mapping and Automated Testing

## Overview
This release introduces a robust, name-based system for mapping internal data sources to Anki fields, replacing the legacy hard-coded index system. It also establishes the project's first automated unit testing suite.

## User Request
- **20260220141406**: Implement flexible field mapping via `config.ini` and verify the solution.

## Implementation Details

### 1. Flexible Field Mapping System
- **Name-based Lookup**: Implemented `get_anki_csv_header()` and `get_field_index_map()` in `kardenwort.py`. This decouples the processing logic from specific column indices, allowing for easier header modifications.
- **Configurable Mapping**: Added support for `[anki_field_mapping.word]` and `[anki_field_mapping.sentence]` sections in `config.ini`. Users can now map any Anki field name to internal data sources (e.g., `lemma`, `source_word`, `source_sentence`).
- **Dynamic Initialization**: Replaced hard-coded row lengths with dynamic initialization based on the header definition.
- **CLI Support**: Added the `--anki-field-mapping` argument to `kardenwort.py` to accept JSON-encoded mapping overrides from the runner.

### 2. Runner and Configuration Enhancements
- **Case Preservation**: Updated `kardenwort_runner.py` to use `config.optionxform = str`, ensuring that CamelCase Anki field names in the configuration are preserved.
- **Runner Integration**: Modified `kardenwort_runner.py` to automatically detect mapping sections and pass them as JSON to the core script.
- **Template Update**: Updated `config.ini.template` with examples and available data sources for custom mapping.

### 3. Automated Testing Suite
- **Base Infrastructure**: Created the project's first dedicated test suite in `tests/test_field_mapping.py`.
- **Package Fix**: Resolved a critical bug in `src/kardenwort/__init__.py` where a broken import prevented the package from being properly imported as a module.
- **Unit Tests**: Implemented 10 comprehensive tests covering:
    - Default/baseline mapping behavior.
    - Custom mapping overrides for word and sentence modes.
    - Handling of unknown fields and missing data sources.
    - Structural consistency between header definitions and index maps.
    - TTS field index validity.

## Verification
- **Baseline Test**: Verified that runs without custom mappings produce identical output to previous versions.
- **Custom Mapping Test**: Successfully verified that mapping `WordSourceAI = source_word` correctly populates the field with inflected forms instead of lemmas.
- **Automated Tests**: All 10 unit tests pass successfully.
