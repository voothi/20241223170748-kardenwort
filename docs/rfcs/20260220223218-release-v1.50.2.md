# RFC: v1.50.2 - Configuration-Driven Anki Field Mapping Finalization

## Overview
This release finalizes the transition to a fully configuration-driven Anki field mapping system. It enforces strict configuration requirements, preserves all translation and context data through a refactored internal data pipeline, and resolves several regressions identified during the integration phase.

## User Request
- **20260220223218**: Finalize the Anki field mapping by ensuring all tests pass, fixing remaining minor errors, and confirming full functionality of the configuration-driven system.

## Implementation Details

### 1. Strict Configuration Enforcement
- **Validation**: Added logic to `kardenwort_runner.py` to verify that `config.ini` contains the essential `[anki_fields]` and mode-specific `[anki_field_mapping.*]` sections.
- **Robustness**: The script now exits with a descriptive error message if these sections are missing, preventing silent failures or misconfigurations.

### 2. Refactored Data Pipeline
- **Centralized Capture**: Introduced `prepare_row_data()` to consolidate all potential field data (source sentence, translations, context, wordlist, index, etc.) before applying mappings.
- **Feature Parity**: Ensured that word mode now has internal access to the same translation and context fields as sentence mode, an improvement over legacy hardcoded logic.
- **Field Name Stability**: Standardized the use of `Quotation` as the primary identity field across both modes, ensuring stable Anki card identification.

### 3. Regression Fixes and Cleanup
- **NameError Fixes**: Resolved variable name mismatches (e.g., `content_end_index` vs `context_end_index`) and initialized `sentence_lemmas_cache` in all processing paths.
- **Word Mode Translations**: Restored missing translation mappings in `[anki_field_mapping.word]` that were inadvertently lost during the initial refactor phase.
- **Clean Configuration**: Updated `config.ini.template` with comprehensive documentation and examples for every available data source.

### 4. Verification and Testing
- **Integration Tests**: Successfully ran end-to-end `mixed-triple` mode extraction (word + sentence) for German text, verifying that all fields populate correctly.
- **Unit Tests**: Updated `tests/test_field_mapping.py` to cover new pipeline logic and verified all tests pass.

## Decision Log
- **Decision: Enforce Configuration Presence**: We decided to make Anki-related config sections mandatory to ensure users are aware of the mapping behavior and to avoid unpredictable defaults.
- **Decision: Unified Data Entry**: We chose to unify the internal data dictionary (`row_data`) across all modes to simplify the mapping logic and enable future data sources to be added centrally.
- **Decision: Quotation as Primary Key**: Reaffirmed `Quotation` as the stable key for Anki updates to maintain compatibility with existing user decks.
