# 20260303154420: Configuration Refinement and Milestone Release v2.0.0

## Overview
This RFC documents the transition to version v2.0.0 of Kardenwort. The primary focus of this release is the centralization of configuration through `config.ini`, the elimination of redundant command-line interface (CLI) complexities, and the standardization of the data extraction pipeline based on flexible field mappings.

## Related Requests
- **20260303154420**: Initial request for checking consistency between commands and utility configuration, resolving duplicate functionality between CLI switches and `config.ini`, and cleaning up obsolete project directories.

## Implementation Details

### Analytics & Decisions
1. **Configuration Centralization (`config.ini`)**:
   - *Decision*: Legacy flags such as `--wordlist-use-br` and `--add-header` were migrated to the `[output_format]` section of `config.ini`.
   - *Rationale*: Hardcoding these options or requiring them as mandatory CLI arguments for every run was error-prone and made automation difficult. Centralizing them allows for persistent, project-wide defaults.
   - *Priority*: CLI arguments still override `config.ini` settings if explicitly provided, maintaining flexibility for one-off overrides.

2. **Automated Extraction Flags**:
   - *Issue*: Previously, users had to manually enable flags like `--add-wordlist-col` or `--add-sentence-index-col`.
   - *Decision*: Refactored `kardenwort.py` to dynamically derive these requirements by inspecting the `anki_field_mapping` in `config.ini`.
   - *Impact*: If a user maps an Anki field to `wordlist` or `sentence_index`, the system automatically activates the necessary processing logic. This reduces the CLI API surface and prevents "silent failures" where a field is mapped but not populated.

3. **Runner Logic Modernization (`kardenwort_runner.py`)**:
   - *Decision*: The runner now acts as a configuration coordinator. It reads the centralized settings from `config.ini` and passes them to the core script only when necessary.
   - *Cleanup*: Obsolete hardcoded argument appends in the runner (which were unused in the core script) were removed.

4. **Repository and Environment Hygiene**:
   - *Decision*: Deleted legacy and potentially confusing directories: `.kiro`, `.qoder`, and the temporary `./a` archive.
   - *Security/Privacy*: Excluded `config.ini` from version control via `.gitignore` and removed it from the Git cache to ensure local user paths and secrets are not leaked, while maintaining `config.ini.template` for new setups.

5. **Milestone Verification**:
   - *Decision*: Introduced automated integration tests (`tests/test_integration.py`) that target the `tests/source_texts` directory.
   - *Scope*: Verified extraction for both German and English in `mixed-triple` mode, ensuring that the new configuration logic correctly produces headers and formatted wordlists.

## Conclusion
Release v2.0.0 transforms Kardenwort from a script-based utility into a configuration-driven tool. By establishing `config.ini` as the single source of truth and automating feature activation via field mapping, we have laid a robust foundation for the advanced testing and linguistic features introduced in subsequent micro-versions.
