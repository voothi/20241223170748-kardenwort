# 20260304005250: Test Suite Refactoring and Release v2.0.4

## Overview
This RFC documents the creation of release v2.0.4 for Kardenwort, incorporating major structural improvements to the project's test suite, which drastically enhance test coverage, maintainability, and regression safety.

### Related Requests
- **20260303230303**: Refactoring Kardenwort Tests, ensuring alignment with best practices, and checking missing `kardenwort.py` integration mapping comparisons.
- **20260304002413**: Restructuring tests into specialized directories and introducing high-level smoke tests.

## Implementation Details

### Analytics & Decisions
1. **Pytest Migration (`test_extraction_flow.py`, `test_runner_args.py`, `test_core_logic.py`)**: 
   - *Decision*: Transitioning from the standard `unittest` framework to `pytest` reduced boilerplate logic via fixtures and parameterization. 
   - *Impact*: Allowed tests to execute dynamic case discovery directly from the `tests/cases/*` directory rather than hardcoding.
2. **Dynamic Config Validation**:
   - *Issue*: Past integration logic explicitly mapped column indices (e.g., checking TSV row index 1) which was highly brittle.
   - *Decision*: Mappings are now extracted at test runtime from `config.ini` `[anki_field_mapping.*]` schemas, making the extraction tests universally robust against future template extensions.
3. **Structured Test Directories**:
   - *Decision*: Tests are now neatly siloed into `tests/unit`, `tests/integration`, and `tests/smoke`. 
4. **Targeted Core Testing (`kardenwort.py`)**:
   - *Issue*: Core linguistic extraction loop `extract_lemmas_from_sentence` and related edge cases (e.g. malformed regex overrides) possessed only 4% coverage.
   - *Fix*: Mocks simulating spacy `Doc` and `Token` objects were added. Direct coverage for `kardenwort.py` surged ~5x to 19% coverage, securing the underlying linguistic engine against processing bugs.
5. **Smoke Tests (`test_smoke.py`)**:
   - *Decision*: A specialized, near-instant test suite was built to strictly verify the CLI boot paths and fast in-memory execution. This provides immediate signal for breaking syntax issues prior to heavier integration routines.

## Conclusion
The v2.0.4 release represents a giant leap in code reliability. By ensuring deep test parameterization, config-aware validation, and core NLP path simulation, subsequent feature additions can be made faster and with far superior confidence.
