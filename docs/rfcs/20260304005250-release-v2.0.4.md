# 20260304005250: Comprehensive Verification and Test Suite Modernization (v2.0.4)

## Overview
This RFC documents the evolution of release v2.0.4, which focused on transforming Kardenwort from a verified script into a robust, professionally tested platform. This was achieved through a two-phase process: first, stabilizing the integration pipeline and runner logic; second, refactoring the entire test suite to modern standards while drastically expanding core coverage.

## Implementation Details

### Phase 1: Integration Verification and Runner Stabilization
Initially, effort was focused on ensuring the "ground truth" of the tool's output was accurate and that the runner behaved predictably.

1. **Runner Bug Fix (`kardenwort_runner.py`)**:
   - *Issue*: `get_script_args` prioritized `config.ini` defaults over explicit CLI arguments for input files.
   - *Fix*: Refactored precedence to ensure CLI arguments always take priority.
2. **Deep TSV/JSON Verification**:
   - *Decision*: Implemented bit-for-bit verification normalized for timestamps.
   - *Verified Metrics*: Strict field order (WordSource at index 1, SentenceSource at index 9) and frequency-based sorting in wordlists.
3. **Metadata Parity**:
   - *Decision*: Added `assert_json_metadata_match` to ensure Anki deck descriptions are correctly generated and structured.

### Phase 2: Test Suite Refactoring and Coverage Expansion
Building on the stable verification layer, the infrastructure was modernized to support future growth.

1. **Pytest Migration**:
   - *Decision*: Transitioned from `unittest` to `pytest` using fixtures and parameterization.
   - *Impact*: Enabled dynamic case discovery from `tests/cases/*`.
2. **Structured Hierarchy**:
   - *Decision*: Siloed tests into `unit/`, `integration/`, and `smoke/` directories.
3. **Core Linguistic Coverage**:
   - *Fix*: Added mocks for spaCy objects to test `kardenwort.py` in isolation. Core unit coverage surged by ~5x (to 19%), protecting the extraction engine.
4. **Smoke Testing**:
   - *Decision*: Created `test_smoke.py` for near-instant validation of CLI boot paths and basic extraction sanity.

## Conclusion
Release v2.0.4 establishes a "Zero Regression" policy for Kardenwort. By first fixing critical runner precedence and then overhauling the test suite with specialized tiers (Smoke, Unit, Integration), we have ensured that the linguistic accuracy and configuration flexibility of the tool remain protected against all future changes.
