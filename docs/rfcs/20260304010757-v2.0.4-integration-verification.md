# 20260304010757: Integration Verification and Runner Bug Fix (v2.0.4)

## Overview
This RFC documents the comprehensive verification of Kardenwort's integration pipeline and a critical fix to the runner logic, ensuring that automated tests accurately reflect production configuration and output requirements for release v2.0.4.

### Related Requests
- **20260303221220**: Updating integration tests to strictly match production CMD options and testing container decks with headers.
- **20260303224311**: Implementing header structure validation and comparison with reference files.
- **20260303225316**: Verification of lemma sets in TSV, field order consistency (WordSource at index 1, SentenceSource at index 9), and frequency-based sorting in `SentenceSourceWordlist`.

## Implementation Details

### Analytics & Decisions
1. **Runner Bug Fix (`kardenwort_runner.py`)**:
   - *Issue*: The `get_script_args` function was incorrectly prioritizing hardcoded `config.ini` defaults over command-line arguments for input files (`--text1-file`, etc.). This caused English integration tests to process German source files.
   - *Decision*: Refactored argument derivation to strictly prioritize explicitly passed command-line arguments over configuration fallbacks.
   - *Impact*: Enabled reliable multi-language integration testing and restored expected CLI behavior for users overriding defaults.

2. **Rigid TSV Verification**:
   - *Decision*: Beyond just checking for file existence, the integration tests now perform deep content inspection of generated TSVs.
   - *Verified Elements*:
     - **Field Order**: Explicitly checks that `WordSource` and `SentenceSource` are at their expected global indices (1 and 9 respectively).
     - **Frequency Sorting**: Validates that the `SentenceSourceWordlist` field contains lemmas sorted by their frequency index (loaded from `data/*-words.csv`).
     - **Lemma Coverage**: Confirms that all expected lemmas from the source text are present in the final export, matching the deduplication scope.
     - **Reference Match**: Uses a strictly controlled set of reference TSVs in `tests/cases/` for exact bit-for-bit (normalized for timestamps) comparison.

3. **Metadata Parity (JSON)**:
   - *Decision*: Implemented `assert_json_metadata_match` to verify the structure and content of generated deck description sidecars.
   - *Normalization*: Added logic to strip dynamic numeric IDs from deck names during comparison to allow for stable testing across different runs.

4. **CMD Script Alignment**:
   - *Decision*: Mirrored the exact argument sets from `scripts/run/cmd/kardenwort_run_*_v3.cmd` into the integration test suite, ensuring that the "out-of-the-box" user experience is what is being tested.

## Conclusion
These updates bridge the gap between "working code" and "verified production-ready logic". By fixing the runner's argument precedence and implementing deep TSV inspection, v2.0.4 guarantees that linguistic extraction and sorting remain stable across releases.
